# FC-09 metadata-first growth, FC-10 work queue, FC-11 contingent migration gate

Status (2026-11-15): **code complete with fixtures; not wired into the live
crawler yet** (that wiring needs the single serialized writer to be accepted
first). Migration 13 adds `acquisition_queue` and `work_items`.

## FC-09 — `foia_archive/acquisition.py`
`growth_mode(archive_bytes, cap)` switches to `metadata_only` at the cap (8.5 GB
document cap); discovery continues and `enqueue_remote_only()` queues every
not-yet-preserved record, agencies with nothing preserved first.
`next_acquisitions(budget_bytes)` plans fetches that fit known sizes into the
remaining headroom, takes an unknown-size record only alone, and skips links
with `broken`/`blocked` availability evidence (`record_availability`). Queued
records remain `metadata_only` in FC-13 exports and the coverage page.

## FC-10 — `foia_archive/work_queue.py`
Idempotent `(kind, key)` items; atomic batch leasing (`BEGIN IMMEDIATE`) with a
per-host concurrency ceiling; round-robin across agencies weighted by completed
work; lease heartbeat; expired leases return to the pool (crash recovery); only
the current holder can complete (stale results refused); exponential backoff to
`DEAD`. A bounded 600-item / 3-worker test with 5% injected failures proves
exactly-once completion, the host ceiling and no starvation. Horizontal scale
beyond one host requires FC-11 first (SQLite stays a single writer).

## FC-11 — `foia_archive/migration_plan.py` (requires explicit spend authorization)
* `storage_cost_estimate()` takes caller-supplied current prices (none are
  hard-coded) and always reports `spend_authorized: false`.
* `migration_gate()` stays closed without an owner record
  `{approved_by, approved_at, monthly_budget_usd ≥ estimate}`.
* `shadow_compare()` checks result/rank parity between the current SQLite FTS
  and a candidate index; `cutover_ready` is always false here.

Plan (not started; needs the gate open): (1) owner approves budget and target
(B2 larger tier for objects; PostgreSQL FTS or a dedicated search index for
metadata/text if SQLite limits are measured); (2) provision in shadow mode;
(3) batch-copy catalog with FC-13 snapshot hashes and object-key continuity
checks; (4) shadow reads until `shadow_compare` parity holds on a fixed query
set; (5) cut over behind a flag with SQLite kept as rollback; (6) only then
lift the single-writer restriction for FC-10 workers.
