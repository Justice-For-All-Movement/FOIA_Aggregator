# FC-05 backfill, FC-06 adaptive adapters, FC-07 content types

Status (2026-11-15): **code complete with fixtures**; no live source traversed.

## FC-05 — `foia_archive/backfill.py`
* `plan_backfill(source_id, start, end, months)` creates `PENDING` date windows
  on the FC-02 cursor ledger (idempotent); each window is a replayable checkpoint.
* `missed_period_queue()` lists unfinished (`PENDING`/`IN_PROGRESS`/`FAILED`)
  windows oldest-first across sources; `BLOCKED` windows are excluded, not retried.
* `backfill_status()` gives verified oldest/newest windows and expected-vs-seen
  counts where the source declares totals.
* `release_windows()` gives per-source oldest/newest published year, records
  per year, empty years inside the span and undated records. Years are metadata only.

## FC-06 — `foia_archive/adapters.py`
* `detect_site_type()` → `sitemap`, `json_api`, `pal`, `html_listing`,
  `document`, `challenge`, `unknown`.
* `raise_if_blocked()` turns 401/403 and CAPTCHA/challenge pages into
  `SourceAccessBlocked` (FC-02 records `BLOCKED`; nothing is solved or evaded).
* `sitemap_pager()` walks sitemap indexes breadth-first as an FC-02 cursor;
  same-host URLs only; DTD/entity declarations anywhere in the document are
  refused; size and fan-out limits.
* `parse_json_listing()` maps documented public JSON APIs by dotted paths
  (items, URL field, next link restricted to the source host, declared total).

## FC-07 — `foia_archive/content_types.py`
* `sniff()` identifies PDF, OOXML (docx/xlsx/pptx), OLE legacy Office, ZIP,
  images, RTF, audio/video and text by signature.
* `safe_zip_members()` expands bundles under member-count, per-member,
  total-size, compression-ratio (100×) and nesting (1) limits, with bounded
  reads, and rejects traversal paths, symlinks and encrypted members.
* `format_coverage()` reports per archived format INDEXED / EMPTY /
  UNSUPPORTED / FAILED / NOT_ATTEMPTED and indexed % of *attempted* only.
Wiring bundle expansion into the downloader and audio/video transcript
metadata are follow-ups.

## Published-date window crawl ("released in the last week") — 2026-11-16

`main.py run --published-since YYYY-MM-DD [--published-until YYYY-MM-DD]`
or `--since-days N` (UTC), plus `--include-unknown-dates`. Workflows use the
same window through `FOIA_PUBLISHED_SINCE`, `FOIA_PUBLISHED_UNTIL`,
`FOIA_PUBLISHED_SINCE_DAYS` and `FOIA_PUBLISHED_INCLUDE_UNKNOWN`
(`refresh-corpus.yml` dispatch inputs, default `since_days=7`, still in the
`foia-b2-single-writer` concurrency group; scheduled runs use the optional
repository variable `FOIA_REFRESH_SINCE_DAYS`).

* Metadata is recorded for every discovered candidate; only documents whose
  detected published date is inside the window are downloaded. Unknown
  dates are skipped unless `--include-unknown-dates`.
* Out-of-window/unknown candidates do not consume the per-source quota, and
  in-window links on a page are processed first.
* Counts (`in_window`, `unknown_date`, `out_of_window`, `admitted`,
  `skipped_download`) are printed by the CLI, logged by the engine and added
  to the expansion job summary. The window joins the run-journal policy
  fingerprint only when set, so existing resumable runs are unaffected.
* Published dates come from explicit `data-*-date` attributes, table columns
  headed Published/Released, `<time>` publication markers, and (new) text
  explicitly labeled *Posted/Released/Published/Release date* next to the
  link. Unlabeled dates in link text (usually the document's own date) are
  deliberately not treated as publication dates.

`scripts/live_probe.py` + `.github/workflows/live-probe.yml` run a bounded,
read-only dry-run window crawl of ten public reading rooms on every PR
(honest UA, 2 s/host, 3 pages/source, no downloads, no B2, no secrets).

### Release-date sources and "newly found" — 2026-11-16 (follow-up)

Migration 15 adds `documents.published_date_source` (`page` > `header` >
`metadata`, the stronger source wins), `documents.newly_found_at` and
`reading_rooms.baseline_completed_at`.

* **page**: date shown next to the link (attributes, table column, `<time>`,
  labeled Posted/Released/Published text).
* **header**: HTTP `Last-Modified` from one polite HEAD per undated *new*
  link (honest UA, SSRF-safe redirects, per-host delay, never retried with
  other headers), at most `crawler.max_head_date_probes_per_source`
  (settings: 25; code default 0) per source per crawl.
* **metadata**: PDF `/ModDate` (else `/CreationDate`) after a download, only
  when nothing better is known.
* **newly found** (`first_seen`, never stored as `published_date`): a source's
  first successful crawl completes its baseline; only records first seen
  *after* that are stamped `newly_found_at`. The migration backfills the
  baseline from `last_successful_crawl_at`, so existing sources do not flood
  the list. Caveat: a later crawl that reaches deeper listing pages than the
  baseline did can mark older items as newly found.

Window crawls (`--since-days`) download items dated in the window **or**
newly found in it; everything else stays metadata-only, within the B2 caps.
`/recent` and `/api/v1/records?published_since=` default to `basis=any`
(dated or newly found), accept `basis=dated|new`, and label each row's date
source (`filter.date_basis` per record in the API envelope; records keep the
pinned v1 shape).
